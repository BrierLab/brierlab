# The learned model

Generated by `node src/card.mjs` from `data/model/eval.json`. Do not edit by hand.

## What it is

A gradient-boosted decision tree model that estimates the chance a Phase 2 or Phase 3 drug trial meets its primary endpoint. It is 400 trees of depth 5 over 92 inputs, written in plain JavaScript with no dependencies (`src/gbm.mjs`, about 150 lines). The same trees run in the browser on the site's How it works page and reproduce every sealed forecast exactly.

It runs beside the language-model forecast. It does not replace it, and nothing here says which of the two is better: that is decided by sealed forecasts on trials that have not reported.

## Data

- 9,248 randomized Phase 2 and 3 drug trials with results posted on ClinicalTrials.gov between 2008 and mid-2026. `src/history.mjs` downloads them; the data is public and free.
- The outcome label is read from the posted p-values on the first primary endpoint. Checked against a careful reading of 203 trials, this rule agreed on 93%.
- Trials that were terminated are left out of training, because their recorded enrollment gives the ending away.

## Inputs

- Facts from the registration record: phase, sponsor type, size, arms, blinding, control, number of endpoints, endpoint type and timing, sites, countries, start year.
- Track records: how earlier trials turned out for the same sponsor, drug, drug at the same and the earlier phase, drug in the same disease, condition, disease category and endpoint wording.

## Guards against hindsight

- A trial's track-record inputs count only results that were public before that trial's own primary completion date. No trial sees its own result or anything later.
- Status, stop reasons, completion dates and results dates are never inputs.
- The registry's drug tags are not used. A drug tends to get a tag once it is well known, which would leak the outcome.
- Known gap: registry records are edited after a trial ends. Enrollment, for example, becomes the actual count. Live performance may therefore be lower than the tests below.

## How it is tested

1. Walk-forward. Train on everything posted before a date, test on the next twelve months, four times. Model settings are chosen here.
2. Held-out. Trials whose results were posted on or after 15 July 2026, never used for training or for choosing settings. This set has now been looked at for two model versions.
3. Learning curve. The same settings trained on random subsets of the history, tested on the held-out trials.

"Skill" is the share of squared error removed compared with always guessing the average success rate. Zero means no better than that guess.

## Limits

- No live trial has been scored yet. Every number above is a test on past trials.
- No comparison with other published models has been run. These numbers are not on any public benchmark, so they say nothing about rank.
- It reads the registry record only. It knows nothing about the drug's biology, earlier data that was never posted to the registry, or news.
- Retraining is run by hand (`npm run retrain`). Each retrain is sealed as a new version before its forecasts are shown.

## Versions

- v1: 68 inputs, 200 trees. Walk-forward skill 19.7%, held-out skill 19.0%, AUC 0.758.
- v2: 92 inputs, 400 trees. Adds disease categories, drug history by phase and by disease, endpoint timing, and a wider settings search. Walk-forward skill 20.4%, held-out skill 20.6%, AUC 0.770.

## Reproduce

```
npm run history            # download the training history (about 290 MB)
node src/train.mjs eval    # walk-forward, held-out and learning-curve tests
node src/train.mjs fit     # train on everything, forecast the open trials
node src/card.mjs          # rewrite this file
```
